class codi.CoraClient(filepath: str = None, **kwargs)

Bases: CoraInterface

High-level client that connects to a running CoraServer.

Extends CoraInterface with a lifecycle handler that automatically reconnects, configures, and sets up the robot connection after any drop. Provides the public API for sending commands, receiving states and frames, and updating robot options.

Parameters:

  • filepath (str, optional) – Absolute path to a YAML or JSON config file.

  • kwargs –

    • host (str) – Robot TCP hostname.

    • ports (dict) – Port mapping (see CoraInterface).

    • use_controller (bool) – Enable gamepad/controller input. Default False.

    • use_camera (bool) – Enable video streaming. Default False.

cleanup()

Disable all options and stop all running threads.

Called automatically by _kill(). Safe to call multiple times.

configure()

Half-close directional sockets to enforce read-only/write-only modes.

Shuts down the write end of read-only sockets and the read end of write-only sockets, preventing accidental use in the wrong direction. Applies to states_socket, video_socket, and command_socket.

configure_robot(**kwargs)

Update feature flags and send the new configuration to the server.

Accepts the active client flags, filters deprecated compatibility arguments, maps legacy use_camera values to the config schema, reconciles threads, then encodes and sends the config payload over config_socket.

Parameters:

kwargs –

  • use_controller (bool) – Enable gamepad input.

  • use_camera (bool) – Enable video streaming.

connect()

Connect all sockets to the server with automatic retry.

Iterates over every entry in sockets and calls _connect_with_retry(). Marks each socket as alive after a successful connection.

Raises:

ConnectionError – If any socket cannot connect within the retry budget.

init_threads()

Register thread metadata and targets for the receive sockets.

Populates the thread sub-dict for video_socket and states_socket with targets pointing to receive_frame() and receive_states() respectively.

Does not start any threads; call start_thread() or update_options() for that.

kill_options()

Disable optional feature flags used by the client.

Called by cleanup() before tearing down threads.

receive_frame()

Continuously receive and decode video frames from the server.

Runs _socket_receive_loop() on video_socket. Decoded frames are accessible via get_frame().

Intended to run in the dedicated video thread started by start_thread().

receive_states()

Continuously receive robot state messages from the server.

Runs _socket_receive_loop() on states_socket. Decoded messages are stored in sockets['states_socket']['message'] and accessible via get_states().

Intended to run in the dedicated states thread started by start_thread().

reconcile_threads(active_set)

Start or stop socket threads to match a desired active set.

Compares each socket’s current running state against active_set and calls start_thread() or stop_thread() as needed. Sockets without a thread sub-dict are silently skipped.

Parameters:

active_set (iterable of str) – Iterable of socket names that should be running, e.g. {'states_socket', 'video_socket'}.

setup()

Initialise threads and apply current option flags.

Called once the connection is configured. Runs init_threads() to register thread targets, then update_options() to start whichever receive threads are required.

start_thread(name)

Start the receive thread for a named socket if it is not already running.

Clears the stop event and spawns a new daemon thread using the target registered in init_threads().

Parameters:

name (str) – Socket key, e.g. 'video_socket' or 'states_socket'.

stop_thread(name)

Stop the receive thread for a named socket.

Sets the stop event, joins the thread with a 1-second timeout, and clears the thread reference.

Parameters:

name (str) – Socket key to stop.

update_options()

Reconcile running threads with current feature flags.

Builds the set of sockets that should be active based on use_camera and the always-on states_socket, then calls reconcile_threads().

Call this after changing any use_* attribute to apply the update.

class codi.CoraServer(filepath: str = None, **kwargs)

Bases: CoraInterface

Server-side interface that accepts connections from a CoraClient.

Binds the command, states, video, and config sockets, listens for the client, and exposes methods to push state and video data back to the client while receiving commands and configuration updates.

The server’s lifecycle handler automatically re-accepts a new client connection after a disconnect, making it resilient to client restarts.

Parameters:

  • filepath (str, optional) – Absolute path to a YAML or JSON config file.

  • kwargs – Host and ports mapping (see CoraInterface).

accept_connections()

Accept one client connection on each socket.

Uses select.select() to wait non-blockingly for incoming connections. Loops until all sockets have an accepted connection or _running becomes False. Marks every socket as alive once all connections are established.

bind()

Bind and begin listening on all sockets.

Calls socket.bind() and socket.listen() (backlog 1) on every socket using the configured host and port. Prints a confirmation when all sockets are listening.

cleanup()

Shut down and close all accepted client connections.

Iterates over sockets, calling shutdown and close on each connected socket. Silently ignores OSError to handle already-closed sockets gracefully.

connect()

Accept incoming client connections if the server is running.

Delegates to accept_connections().

receive_command()

Continuously receive motion commands from the client.

Runs _socket_receive_loop() on command_socket. Decoded commands are stored in sockets['command_socket']['message'] and retrievable via get_command().

Intended to run in the dedicated command thread started by start_threads().

receive_config()

Continuously receive configuration updates from the client.

Runs _socket_receive_loop() on config_socket. Decoded configs are accessible via get_config().

Intended to run in the dedicated config thread started by start_threads().

start()

Bind all sockets and launch the lifecycle handler.

This is the primary entry point for bringing a CoraServer online. After this call the server waits for a client to connect.

start_threads()

Start receive threads for command_socket and config_socket.

Populates thread metadata for each socket in threaded_sockets and spawns daemon threads targeting receive_command() and receive_config() respectively.

stop_threads()

Stop all threads in threaded_sockets.

Sets each thread’s stop event, joins with a 1-second timeout, and clears the thread reference.
